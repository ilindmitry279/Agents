A friendly introduction

AI agents: models that
don't just answer, but act.

An AI agent is a language model placed in a loop: it gets a goal, decides what to do, uses tools, looks at the results, and keeps going until the job is done.

See an agent think ▶ Start from basics

Chatbot vs. agent

Both use the same kind of model. The difference is autonomy: a chatbot replies once; an agent works through many steps toward a goal.

💬 Chatbot

  • One question → one answer
  • Knows only what's in its training and the prompt
  • You do the follow-up work
  • Can't change anything in the world

🤖 Agent

  • One goal → many steps
  • Looks things up, reads files, calls APIs
  • Checks its own results and corrects course
  • Takes real actions (with guardrails)

The agent loop

Nearly every agent runs the same cycle. Pick a task and press play to watch it step through.

1

2
ThinkPlan the next step
3

4

5
FinishOr loop back to Think

What an agent is made of

Strip away the branding and most agents share the same building blocks.

🧠

Model

The language model that reads context and decides the next action.

🛠️

Tools

Functions the model can call: web search, code execution, file access, APIs, databases.

🗂️

Memory

Short-term context for the current task, plus optional long-term notes that persist between sessions.

🧭

Planning

Breaking a big goal into steps, and revising the plan when something unexpected happens.

🔁

Control loop

The code that runs the model, executes tool calls, and feeds results back in.

🛡️

Guardrails

Permissions, approvals, sandboxes, and limits that keep the agent's actions safe.

Common patterns

From a single loop to teams of cooperating agents.

One model, one loop, many tools

The simplest and most common design. The model keeps calling tools until it decides it's done.

while True:
    reply = model(messages, tools=TOOLS)
    if not reply.tool_calls:
        return reply.text            # task finished
    for call in reply.tool_calls:
        result = run_tool(call.name, call.args)
        messages.append(tool_result(call.id, result))

Fixed steps, model inside each one

You define the order of steps in code (e.g. extract → classify → draft → review). More predictable, less autonomous. Great when the process is well known.

data    = model("Extract key facts from: " + doc)
label   = model("Classify this request: " + data)
draft   = model(f"Write a {label} reply using: {data}")
final   = model("Check this draft for errors: " + draft)

An orchestrator with specialist helpers

A lead agent splits the work and hands pieces to sub-agents (researcher, coder, reviewer), then combines their results. Useful for large tasks that can run in parallel.

plan     = orchestrator.plan(goal)
results  = parallel(subagent(task) for task in plan.tasks)
answer   = orchestrator.combine(results)
verified = reviewer.check(answer)

Where agents are useful

Agents shine on tasks with many steps, clear success criteria, and tools to check the work.

💻

Software development

Reading a codebase, writing changes, running tests, and fixing what breaks.

🔎

Research

Searching many sources, cross-checking facts, and writing a cited summary.

📊

Data analysis

Querying databases, cleaning data, running statistics, and building charts.

🎧

Customer support

Looking up orders, following policies, and escalating tricky cases to humans.

🗓️

Personal assistance

Sorting email, scheduling meetings, and preparing drafts for your approval.

⚙️

Operations

Monitoring systems, triaging alerts, and running routine fixes.

Limits and risks

More autonomy means more ways to go wrong. Good agents are designed with these in mind.

Compounding errors

A small mistake early on can snowball over many steps.

Prompt injection

Malicious text in a web page or document may try to hijack the agent.

Unsafe actions

Deleting data or sending messages should require human approval.

Cost and speed

Many model calls add up in time and money; not every task needs an agent.

FAQ

Quick answers to common questions.

Is an AI agent conscious or self-aware?

No. It's a model producing text in a loop, plus code that runs the tools it asks for. "Deciding" is a useful shorthand, not a claim about minds.

Do I need a special model to build an agent?

You need a model that supports tool use (function calling). Most modern large language models do.

When should I NOT use an agent?

When a single prompt or a simple fixed script does the job. Agents add cost, latency, and unpredictability — use them when the flexibility is worth it.

How do I keep an agent safe?

Give it the fewest tools and permissions it needs, run code in a sandbox, require approval for irreversible actions, log everything, and set step and budget limits.
